# Plan: Neovim cómodo con mouse, Python/uv y TypeScript, portable en un solo archivo

## Contexto

Quieres usar Neovim con el mouse "al 100 %", dividir la pantalla en vertical y horizontal, copiar y pegar fácil, buscar en el árbol, trabajar con uv/Python/TypeScript, tener una fuente linda y poder llevar la configuración a cualquier máquina.

Lo que encontré en tu máquina (WSL2 Ubuntu 24.04 + Windows Terminal 1.24):

| Hallazgo | Consecuencia |
|---|---|
| Neovim **0.9.5** (apt). Lo último estable es **0.12.6** | Casi todo lo moderno exige 0.11–0.12 (LSP nativo, treesitter, menú de clic derecho). Es el paso 0. |
| `~/.config/nvim/init.lua` (157 líneas): lazy.nvim, nvim-tree, bufferline, catppuccin, markdown | Sin LSP, autocompletado, buscador, ni ajustes de mouse o portapapeles. Se reescribe conservando tus atajos. |
| `render-markdown.log`: "no treesitter parser found" | No hay compilador C (`gcc`) y Neovim es viejo. Sin compilador no hay resaltado de Python/TS. |
| `sudo` pide contraseña; no hay `python3-venv` | Un comando lo ejecutas tú. Las herramientas Python se instalan con `uv tool` (no con pip). |
| La Nerd Font está en `~/.local/share/fonts` (Linux) y Windows Terminal no tiene fuente configurada | Windows Terminal dibuja con fuentes **de Windows**: por eso los iconos salen como cuadros. |
| `DISPLAY` de WSLg + `xclip` instalados; `win32yank.exe` disponible | La autodetección caería en xclip (inestable). Se fija `win32yank`, que respeta acentos. |
| Proyectos: TS 5.x en los 24; 12 `uv.lock`; ruff en 5 de 17; Prettier en 2 | `vtsls` por defecto, y formateo al guardar solo donde ya está configurado. |
| `gh` con token inválido y SSH a GitHub rechazado | Para publicar el repo necesitas `gh auth login`. |
| Tienes un `nvim .` abierto ahora mismo | Todo se construye aparte y se cambia al final; no te interrumpo. |

Tus decisiones: **repo privado en GitHub**, **JetBrainsMono Nerd Font** (con ligaduras), **formatear al guardar solo si el proyecto lo configura**.

Interpreto "abrir tab vertical y horizontal" como **dividir el editor** a la derecha y hacia abajo (como *Split Right / Split Down* de VS Code). Si te referías a otra cosa, dímelo al revisar.

## Qué vas a tener

| Pedido | Cómo queda |
|---|---|
| Mouse al 100 % | Menú de clic derecho en español según dónde hagas clic (editor, árbol, pestaña), botones clicables, pestañas, barra de desplazamiento arrastrable, documentación al dejar el puntero quieto. Detalle abajo. |
| Dividir vertical/horizontal | Botones en la barra de cada ventana, entradas en los menús, y `Espacio v` / `Espacio h`. Los bordes se arrastran para redimensionar. |
| Copiar y pegar fácil | Portapapeles de Windows integrado: `Ctrl+C`/`Ctrl+X`/`Ctrl+V`, `y`/`p`, clic derecho y clic central. `Shift+flechas` para seleccionar. |
| Buscar en el árbol | En el árbol: `/` búsqueda difusa en todas las subcarpetas (con vista previa; el árbol salta al archivo) y `f` para filtrar lo visible. También desde el clic derecho. |
| uv + Python | `ruff` y `basedpyright` instalados con `uv tool`; detecta el `.venv` del proyecto; `Espacio r` ejecuta con `uv run`; `:Uv sync`, `:Uv add …`. |
| TypeScript | `vtsls` (proyectos TS 5/6) o el servidor nativo de TS 7 (`tsc --lsp`) elegido solo según la versión del proyecto; ESLint; Prettier donde esté configurado. |
| Fuente linda | JetBrainsMono Nerd Font instalada en Windows y puesta por defecto en Windows Terminal. |
| Mejor UX | Autocompletado, barra de estado, ayuda de atajos (which-key), notificaciones, guías de indentación, marcas de git, cierre automático de paréntesis, recarga automática si otro programa (p. ej. Claude Code) cambia el archivo. |
| Fácil de transportar | Repo privado con 1 archivo de configuración + versiones fijas + instalador de un comando. |

## Archivos

Todo vive en `~/.config/nvim/` (que pasa a ser el repo git):

- `init.lua` — **reescrito**. Único archivo de configuración, con secciones y comentarios en español.
- `lazy-lock.json` — **regenerado**. Fija la versión exacta de cada plugin para que en otra máquina quede idéntico.
- `bootstrap.sh` — **nuevo**. Prepara una máquina: Neovim 0.12.6, prerrequisitos, fuente, plugins.
- `README.md` — **nuevo**, breve: instalación en 2 comandos y chuleta de atajos/mouse.

En Windows: fuentes de tu usuario y `settings.json` de Windows Terminal (solo `profiles.defaults.font.face`, con respaldo).

Se reutiliza de lo actual: tus atajos (`init.lua:141-157`), la configuración e iconos de nvim-tree (`init.lua:37-84`), el desplazamiento de bufferline sobre el árbol (`init.lua:113-129`), el arranque de lazy.nvim (`init.lua:2-13`, cambiando `vim.loop` por `vim.uv`), catppuccin, render-markdown y markdown-preview. Las fuentes ya descargadas en `~/.local/share/fonts` se copian a Windows sin bajar nada.

## Diseño de `init.lua`

1. **Encabezado**: instalación en máquina nueva y chuleta.
2. **`OPC`**: tabla de opciones al inicio para ajustar sin buscar (`nerd_font`, `formato_al_guardar = 'proyecto'|'siempre'|'nunca'`, `hover_mouse`, `python_lsp`).
3. **Guarda de versión, lo primero del archivo**: con Neovim < 0.12 carga solo lo básico (mouse, portapapeles, atajos) y avisa cómo actualizar. Va antes del arranque de lazy porque `vim.uv` no existe en 0.9.5.
4. **Opciones**: `mouse=a`, `mousemoveevent`, `splitright/splitbelow`, `confirm`, `undofile`, `keymodel=startsel,stopsel`, `autoread` + `checktime`, pliegues con columna clicable. `mousemodel` se deja en su valor por defecto (`popup_setpos`): el menú contextual depende de él.
5. **Portapapeles** según plataforma: WSL → `win32yank`; si falta, OSC 52 para copiar y PowerShell para pegar con `[Console]::OutputEncoding` en UTF-8 (sin eso los acentos llegan rotos). SSH → OSC 52. Resto → autodetección. `clipboard=unnamedplus`.
6. **Atajos** sin plugins (tabla abajo).
7. **Mouse**: menú `PopUp` nativo reconstruido en el evento `MenuPopup` según el tipo de ventana (se quita el menú por defecto en inglés limpiando el grupo `nvim.popupmenu`); barra de ventana (`winbar`) con regiones clicables solo en ventanas de archivos.
8. **Plugins** (lazy.nvim, 20): catppuccin, nvim-web-devicons, nvim-tree, bufferline, lualine, snacks (buscador, terminal, notificaciones, guías, cierre de buffers), which-key, gitsigns, nvim-scrollview, hover.nvim, nvim-treesitter (`main`), mason + mason-lspconfig + mason-tool-installer, nvim-lspconfig, blink.cmp, conform, mini.pairs, render-markdown, markdown-preview. Sale `mini.icons`.
   - `blink.cmp` con `version = '1.*'`: solo las versiones etiquetadas traen el binario precompilado; sin eso intenta compilar con `cargo` (no instalado) y avisa en cada arranque.
9. **Lenguajes**:
   - Treesitter (`main`) ya no activa nada solo: un autocmd `FileType` llama `vim.treesitter.start()` y fija `indentexpr`/`foldexpr` por buffer. Los parsers se piden con `install{…}` solo si existen `tree-sitter` y un compilador; el `build` de lazy lleva la misma condición. Sin ellos queda el resaltado básico, sin errores.
   - Parsers: python, typescript, tsx, javascript, json, yaml, toml, html, css, bash, dockerfile, sql, diff, gitcommit, regex (más los 7 que trae Neovim).
   - Python: `uv tool install ruff` y `basedpyright` si faltan (asíncrono, con aviso). `basedpyright` en modo `standard` y con `python.pythonPath` en `<raíz>/.venv/bin/python` cuando existe.
   - TypeScript: `vtsls` y `tsc` envueltos con `root_dir` mutuamente excluyente: se lee `node_modules/typescript/package.json`; si es ≥ 7 usa `tsc`, si no `vtsls`. Nunca los dos a la vez. `eslint` solo donde hay config.
   - Mason instala `vtsls`, `eslint-lsp` y `prettier` (todos npm; nada de pip).
10. **Formato** (conform): Python → ruff; web → prettier. Al guardar solo si hay `[tool.ruff]`/`ruff.toml` o config/dependencia de Prettier/Biome. Manual siempre con `Espacio cf` o clic derecho. Interruptor `Espacio of`.
11. **uv y ejecución**: `Espacio r` ejecuta el archivo en un terminal inferior (`uv run` para Python, `node`/`tsx` para JS/TS). Un solo comando `:Uv <args>` corre `uv` en la raíz del proyecto (`:Uv sync`, `:Uv add requests`).
12. **Aviso de requisitos**: una vez por sesión, si falta algo esencial (compilador, `tree-sitter`, `uv`, `node`, `rg`), lo dice y remite a `bootstrap.sh revisar`.

### Atajos (`Espacio` = líder)

| Grupo | Atajos |
|---|---|
| Conservados | `Espacio e` árbol · `Espacio w` guardar · `Espacio x` cerrar pestaña · `Espacio y` copiar archivo entero · `Espacio m` vista previa Markdown · `Tab`/`Shift+Tab` pestañas |
| Divisiones | `Espacio v` vertical · `Espacio h` horizontal · `Espacio q` cerrar · `Ctrl+h/j/k/l` moverse |
| Estilo VS Code | `Ctrl+S` guardar · `Ctrl+C`/`Ctrl+X` copiar/cortar · `Ctrl+V` pegar · `Ctrl+Z`/`Ctrl+Y` deshacer/rehacer · `Ctrl+A` todo · `Ctrl+P` buscar archivo · `Ctrl+F` buscar en el archivo · `Shift+flechas` seleccionar · `Alt+↑/↓` o `Alt+j/k` mover línea · `F2` renombrar · `F12` definición |
| Buscar | `Espacio ff` archivos · `fg` texto · `fb` abiertos · `fr` recientes |
| Código | `gd` definición · `K` documentación · `Espacio ca` acciones · `cf` formatear · `cd` diagnóstico |
| Ejecutar | `Espacio r` archivo · `Espacio t` terminal · `Espacio ps` uv sync · `Espacio pa` uv add |
| Opciones | `Espacio of` formato al guardar · `oh` pistas de tipos · `ow` ajuste de línea |

- Se evitan corchetes y símbolos que en teclado español requieren AltGr.
- En Windows Terminal, `Ctrl+V` lo resuelve el propio terminal (pega antes de que Neovim lo vea); el atajo de Neovim cubre los demás terminales. Por eso la selección en bloque es `Ctrl+Q`.
- Windows Terminal reserva algunas teclas (p. ej. `Alt+flechas` mueve el foco entre paneles), así que cada atajo con `Alt` tiene alternativa con letras.

## Pasos

Se construye todo **aparte**, con `NVIM_APPNAME=nvim-next` (`~/.config/nvim-next`, con su propia carpeta de plugins y datos). Tu Neovim actual sigue intacto hasta el paso 6.

0. **Repo**: `~/.config/nvim-next` con `git init`; primer commit = tu configuración actual tal cual, para tener historial y vuelta atrás.
1. **`bootstrap.sh`**, con subcomandos (`todo`, `nvim`, `fuente`, `plugins`, `revisar`) e idempotente:
   - Neovim v0.12.6 (`nvim-linux-x86_64.tar.gz`) en `~/.local/opt/`, versión fijada con variable para cambiarla. Durante el desarrollo lo invoco por ruta completa.
   - `tree-sitter` v0.27.1 (binario de GitHub, no npm) en `~/.local/bin`; `uv` con su instalador oficial si falta; enlace `fd` → `fdfind`.
   - Prerrequisitos por `apt`. Si no puede usar `sudo` sin interacción, imprime el comando exacto. **Se detiene antes de instalar plugins si no hay compilador**, para no dejar una instalación a medias.
   - Respeta `NVIM_APPNAME`.
2. **Tú**: `sudo apt-get install -y build-essential fd-find`. Sigo con lo que no depende de eso.
3. **`init.lua` por capas**, verificando cada una antes de la siguiente:
   a. núcleo sin plugins (opciones, portapapeles, atajos, menú contextual, barra de ventana);
   b. interfaz (tema, árbol, pestañas, estado, snacks, which-key, gitsigns, barra de desplazamiento);
   c. lenguajes (treesitter, mason, LSP, autocompletado, formato, hover);
   d. extras (comando `:Uv`, ejecutar archivo, aviso de requisitos).
   **a–c son el núcleo a entregar; d no bloquea.** Las opciones de cada plugin se confirman contra su `doc/` ya clonado, no de memoria.
4. **Fuente**: copiar los 4 estilos de `JetBrainsMonoNerdFont-*.ttf` a `%LOCALAPPDATA%\Microsoft\Windows\Fonts`, registrar cada uno en `HKCU\Software\Microsoft\Windows NT\CurrentVersion\Fonts` (por usuario, sin admin), respaldar `settings.json` y poner `profiles.defaults.font.face = "JetBrainsMono Nerd Font"`. Es la rama WSL de `bootstrap.sh fuente`.
5. **Verificación completa** (sección siguiente).
6. **Cambio**: respaldo `~/.config/nvim.bak-20261010.tar.gz`; `nvim-next` pasa a ser `~/.config/nvim`; enlace `~/.local/bin/nvim` → 0.12.6 (va antes que `/usr/bin` en tu PATH; el de apt no se toca); `bootstrap.sh plugins` sobre la carpeta real, que sirve de segunda prueba del instalador; borrar las carpetas `nvim-next` de datos.
7. **Publicar**: `README.md`, commits (con la skill `commit`), y cuando ejecutes `gh auth login`: `gh repo create nvim-config --private --source ~/.config/nvim --push`. En otra máquina: `git clone … ~/.config/nvim && ~/.config/nvim/bootstrap.sh`.

### Lo que necesito de ti

1. Ejecutar el comando `sudo` del paso 2 (pide tu contraseña).
2. Tras el paso 6: cerrar y reabrir Windows Terminal (para la fuente) y tu `nvim`.
3. Ejecutar `gh auth login` antes del paso 7.

- `nvim --version` → 0.12.6; `nvim --headless "+Lazy! restore" +qa` sin errores; `:checkhealth` sin `ERROR` en portapapeles, mason, treesitter y LSP.
- **Máquina nueva**: `NVIM_APPNAME=nvim-next bootstrap.sh` parte de carpetas de datos vacías; debe quedar funcionando sin pasos manuales.
- **Mouse**: clic derecho muestra el menú correcto en editor, árbol y pestaña; elegir "Dividir a la derecha" aumenta el número de ventanas; lo mismo con los botones de la barra; doble clic en el árbol abre; arrastrar la barra de desplazamiento mueve la vista; mover el puntero abre el flotante de documentación.

- **Portapapeles**: copiar una línea con `áéíóú ñ` y leerla con `powershell.exe Get-Clipboard`; pegar el camino inverso. Medir la demora de `yy`; si se nota, se quita `unnamedplus` y quedan los atajos explícitos.
- **Python/uv**: abrir un archivo de `~/projects/negritas` (solo lectura) → `ruff` y `basedpyright` conectados, `pythonPath` en su `.venv`, sin "import no resuelto" de dependencias instaladas.
