# Plan: integrar tmux con Neovim y dejarlo portable en `nvim-config`

## Contexto

Hoy tmux y Neovim conviven pero no están integrados, y `~/projects/nvim-config` tiene que ser la única fuente que lleves a cualquier máquina. Revisé el estado real antes de proponer nada:

| Hallazgo | Consecuencia |
|---|---|
| tmux está en modo de teclas **emacs** (no hay `EDITOR`) | Tus tres atajos `copy-mode-vi` (copiar al soltar el clic, `v`, `y`) **hoy no se aplican**. Actúa el valor por defecto: copia y sale del modo copia. |
| `copy-pipe "xclip …"` escrito a mano | Depende de WSLg/X11. No sirve tal cual en otra máquina. |
| `focus-events off` | Neovim no se entera cuando vuelves al panel, así que no recarga los archivos que cambió otro programa. |
| `default-terminal screen-256color` | Funciona, pero `tmux-256color` (disponible aquí) es el correcto para cursiva y subrayados. |
| Sin atajos `Ctrl+h/j/k/l` en tmux | En Neovim solo se mueven entre divisiones; no cruzan a los paneles de tmux. |
| `win32yank.exe` existe solo porque tienes Neovim instalado en Windows | En otra máquina WSL no estará, y lo prefieren tanto Neovim como tmux para el portapapeles. |
| `bootstrap.sh` solo conoce Neovim | El enlace de `~/.tmux.conf` lo hice a mano; en una máquina nueva no se crearía. |

**Mecanismo ya probado.** Antes de escribir este plan corrí una sonda con un tmux y un Neovim aislados (sin tocar tus archivos), enviando teclas y eventos de mouse por un terminal simulado. Resultado: `Ctrl+h/j/k/l` cruza en ambos sentidos, no da la vuelta en los bordes, respeta el zoom, con un solo panel las teclas llegan intactas al programa, y el foco, los clics y el movimiento del puntero llegan a Neovim a través de tmux. El plan usa exactamente ese esquema.

## Qué cambia para ti

| Tema | Cómo queda |
|---|---|
| Moverse | `Ctrl+h/j/k/l` pasa entre divisiones de Neovim y paneles de tmux como si fueran lo mismo. No da la vuelta en los bordes y no sale de un panel ampliado (zoom). |
| Copiar en tmux | Se activa el modo vi, que es lo que tu configuración pretendía: arrastrar con el mouse copia y **se queda donde está** (`q` o `Esc` para salir); `v` selecciona, `y` copia y sale. Va al portapapeles del sistema en cualquier plataforma. |
| Recarga de archivos | Al volver al panel de Neovim se recargan los archivos que cambió otro programa (p. ej. Claude Code). |
| Aspecto | Subrayado ondulado en los errores y `TERM` correcto dentro de tmux. |
| Máquina nueva | `bootstrap.sh` enlaza `~/.tmux.conf`, y en WSL instala `win32yank` si falta. |

**Costo conocido de este esquema:** cuando una ventana de tmux tiene **más de un panel**, en los paneles de shell `Ctrl+l` (limpiar pantalla) y `Ctrl+k` (borrar hasta el final) pasan a navegar. Para enviar la tecla original: `prefijo + Ctrl+l` y `prefijo + Ctrl+k`. Con un solo panel todo funciona como siempre.

## Diseño

### `tmux/tmux.conf`

```tmux
# ── Básico ──────────────────────────────────────────────────────────
set -g mouse on
set -g history-limit 50000
set -g allow-rename off
set -s escape-time 0
set -g focus-events on      # Neovim recarga archivos al volver al panel

# ── Terminal: color real y subrayados ───────────────────────────────
if-shell 'infocmp tmux-256color' \
  { set -g default-terminal 'tmux-256color' } \
  { set -g default-terminal 'screen-256color' }
set -as terminal-features ',xterm-256color:RGB:usstyle'

# ── Portapapeles del sistema (gana la última línea que coincida) ────
set -s set-clipboard on     # OSC 52: también funciona por SSH
if-shell '[ -n "$DISPLAY" ] && command -v xclip'           { set -s copy-command 'xclip -selection clipboard -i' }
if-shell '[ -n "$WAYLAND_DISPLAY" ] && command -v wl-copy' { set -s copy-command 'wl-copy' }
if-shell 'command -v pbcopy'                               { set -s copy-command 'pbcopy' }
if-shell 'command -v clip.exe && command -v iconv'         { set -s copy-command 'iconv -f utf-8 -t utf-16le | clip.exe' }
if-shell 'command -v win32yank.exe'                        { set -s copy-command 'win32yank.exe -i --crlf' }

# ── Copiar con teclas de Vim ────────────────────────────────────────
setw -g mode-keys vi
bind -T copy-mode-vi v send -X begin-selection
bind -T copy-mode-vi y send -X copy-pipe-and-cancel
bind -T copy-mode-vi MouseDragEnd1Pane send -X copy-pipe   # copia y se queda en el lugar

# ── Ctrl+h/j/k/l entre paneles y divisiones de Neovim ───────────────
# La tecla pasa al programa si es Neovim, si hay un solo panel o si está ampliado.
%hidden EN_APP='#{||:#{m:*vim*,#{pane_current_command}},#{||:#{==:#{window_panes},1},#{window_zoomed_flag}}}'
bind -n C-h if -F "$EN_APP" { send-keys C-h } { if -F '#{==:#{pane_at_left},0}'   { select-pane -L } }
bind -n C-j if -F "$EN_APP" { send-keys C-j } { if -F '#{==:#{pane_at_bottom},0}' { select-pane -D } }
bind -n C-k if -F "$EN_APP" { send-keys C-k } { if -F '#{==:#{pane_at_top},0}'    { select-pane -U } }
bind -n C-l if -F "$EN_APP" { send-keys C-l } { if -F '#{==:#{pane_at_right},0}'  { select-pane -R } }
bind C-l send-keys C-l      # prefijo + Ctrl+l: limpiar pantalla
bind C-k send-keys C-k      # prefijo + Ctrl+k: borrar hasta el final
```

- `copy-pipe` sin argumento usa `copy-command` (confirmado en el manual de tmux 3.4), así que la detección de plataforma se hace una sola vez.
- `clip.exe` a secas rompe los acentos; por eso va con `iconv` y solo como respaldo de `win32yank`.
- La sintaxis exacta (`%hidden`, llaves) se valida al cargar el archivo; la lógica es la de la sonda.

### `nvim/init.lua`

Los atajos simples (`<C-w>h`…) se quedan en el bloque básico, que debe funcionar en Neovim viejo. En la sección 0.12 se reemplazan por:

```lua
-- En el borde de Neovim, Ctrl+h/j/k/l pasa al panel vecino de tmux
for tecla, d in pairs({ h = { 'L', 'left' }, j = { 'D', 'bottom' }, k = { 'U', 'top' }, l = { 'R', 'right' } }) do
  map('n', '<C-' .. tecla .. '>', function()
    local antes = vim.api.nvim_get_current_win()
    vim.cmd.wincmd(tecla)
    if vim.api.nvim_get_current_win() == antes and vim.env.TMUX then
      vim.system({ 'tmux', 'if-shell', '-F',
        ('#{&&:#{==:#{window_zoomed_flag},0},#{==:#{pane_at_%s},0}}'):format(d[2]), 'select-pane -' .. d[1] })
    end
  end, { desc = '…' })
end
```

En el árbol, nvim-tree trae `Ctrl+k` como "información del archivo" y taparía la navegación: se comprueba en `:h nvim-tree-mappings-default` y, si es así, se libera en `on_attach` (`nvim/init.lua`, bloque de nvim-tree) y la información pasa a una tecla libre.

### `nvim/bootstrap.sh`

Se reutilizan `tiene`, `es_wsl`, `version_ok` y el patrón de `enlazar_config`.

- **`paso_tmux`** (subcomando `tmux`, incluido en `todo` antes de `plugins`): si existe `../tmux/tmux.conf`, enlaza `~/.tmux.conf` hacia él. Si ya hay un archivo normal, lo respalda como `~/.tmux.conf.bak-FECHA`. Idempotente. Avisa si tmux es anterior a 3.2 (`copy-command` y `terminal-features` lo requieren).
- **`paso_herramientas`**: agrega `tmux` a los paquetes del sistema; en WSL, si `win32yank.exe` no está en el PATH, descarga `win32yank-x64.zip` v0.1.1 a `~/.local/bin`.
- **`paso_revisar`**: versión de tmux, enlace de `~/.tmux.conf`, y terminfo `tmux-256color` con su comando de arreglo (`ncurses-term` en Debian/Ubuntu).

## Verificación

Todo sobre el `tmux.conf` **real** del repo y la configuración **real** de Neovim, en un servidor aislado (`tmux -L prueba -f …`) con un terminal simulado que envía teclas y eventos de mouse (el mismo arnés de la sonda):

- **Carga**: `tmux source-file` sin errores ni avisos.
- **`:checkhealth` dentro de tmux**: `escape-time`, `focus-events` y `default-terminal` (compara con `$TERM`) en verde.
- **Navegación**: `Ctrl+h/j/k/l` en ambos sentidos, incluido `Ctrl+h` crudo hacia Neovim (que no lo lea como retroceso), sin vuelta en los bordes, zoom respetado, y desde el árbol de archivos.
- **Un solo panel**: `Ctrl+l` y `Ctrl+k` llegan al shell.
- **Mouse**: el clic derecho dentro de Neovim muestra el menú en español y no el de tmux; el puntero quieto abre la documentación.
- **Foco**: `FocusGained` llega a Neovim al volver al panel.
- **Portapapeles**: selección en modo copia → `copy-command` → se lee con `win32yank.exe -o` y conserva `áéíóú ñ`. Guardo y restauro tu portapapeles.
- **`bootstrap.sh`**: `tmux` con un `HOME` temporal (crea el enlace, respalda, es idempotente); `revisar` en verde con las líneas nuevas; instalación desde cero con `NVIM_APPNAME` para confirmar que no se rompió nada.
- **Regresión fuera de tmux**: Neovim abre un proyecto Python y uno TypeScript con sus servidores, como antes.

Solo tú puedes confirmar: el aspecto del subrayado ondulado en Windows Terminal y la sensación de moverse entre paneles.

## Riesgos

| Riesgo | Salida |
|---|---|
| Por SSH, `TERM=tmux-256color` llega a servidores que no lo conocen y se ven mal los colores | `TERM=xterm-256color ssh host`, o copiar el terminfo una vez: `infocmp -x tmux-256color \| ssh host tic -x -`. Queda en el README; no toco tu `.bashrc`. |
| tmux anterior a 3.2 en otra máquina | `bootstrap.sh revisar` lo avisa. |
| Terminal cuyo `TERM` no es `xterm-256color` | Color real y subrayados dependen de esa línea; se agrega su nombre si hace falta. |
| Terminal que envía `Ctrl+h` al pulsar Retroceso | Con varios paneles, Retroceso navegaría. Windows Terminal no lo hace. |
| macOS y otras distros | El diseño las contempla (`pbcopy`, `wl-copy`, terminfo de respaldo), pero solo puedo probar en esta máquina. |

Cambiar el prefijo de tmux, tema de la barra de estado, atajos para dividir paneles, `.bashrc`, y mover `bootstrap.sh` de carpeta.
